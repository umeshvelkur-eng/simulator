Digital arithmetic laboratory

See how a processor adds — one gate at a time.

Five interactive experiments build up from a single-bit half adder to the parallel adder/subtractor at the heart of an ALU. Every diagram is driven by a real gate-level netlist: flip an input and watch the signal travel through the gates.

Experiments

Quick guide

  1. Pick an experiment from the sidebar. Each one opens in its own workspace and remembers its inputs.
  2. Change inputs with switches, binary text boxes, bit buttons or by clicking input terminals in the diagram.
  3. Watch propagation. Signals advance one gate delay at a time. Use Run, Pause and Step.
  4. Read the results in the output panel, the highlighted truth-table row and the step-by-step calculation.

What the colours mean

  • Green wire, gate or terminal: logic HIGH (1). Moving dashes show the signal flowing while the simulation runs.
  • Grey: logic LOW (0).
  • Dashed amber: the new value has not reached this point yet — it still shows its old value, just like real hardware before it settles.

These are digital arithmetic circuit simulations related to the 8086 ALU — see Connection with Intel 8086.

Documentation

Simulator guide

How to operate the workspaces, what the propagation model means, and how each experiment is organised.

Workspace layout

Every experiment has four sections:

  • Circuit Diagram — the gate-level (or block-level) schematic. Wires, gates and terminals are coloured by their live logic value. Input terminals are clickable.
  • Input Controls — toggle switches for single bits; for multi-bit experiments a binary text box (validated), per-bit switches, +/− buttons, presets, and bit-width selection.
  • Output Display — LEDs, result bits, decimal / signed / hexadecimal values and flags.
  • Truth Table / Explanation — tabs with the truth or bit-wise table, step-by-step calculation, comparisons, and the lab-record theory (aim, theory, Boolean expressions, procedure, result).

Propagation model

Each gate has a delay of one unit. A signal’s arrival time t is the length of the longest gate path from the inputs (the “Propagation” meter under each diagram). When an input changes, the simulator reveals level 1, then level 2, and so on. Signals that have not been reached keep their previous value and are drawn dashed amber. This structural (worst-case) model makes ripple delay and look-ahead speed-up directly visible.

Entering binary numbers

  • Use the BIN / DEC / HEX switch above each number box to type a custom value in binary, decimal or hexadecimal. The choice is remembered.
  • Binary: 0s and 1s (spaces, underscores and a 0b prefix are accepted; shorter values are zero-padded). Decimal: 0 … 2ⁿ−1, and in the adder/subtractor and 8086 demo also negative values down to −2ⁿ⁻¹ (stored as two’s complement). Hex: 0–9 / A–F with optional 0x prefix or h suffix.
  • Invalid characters or values outside the bit width show an error and the previous valid value is kept.
  • Arrow ↑ / ↓ in the text box increments / decrements (wrapping around).

Lab record format

The Theory tab of each experiment follows the usual record structure: Aim, Theory, Boolean expressions, Circuit diagram, Procedure and Result. The Result paragraph updates with the inputs you are currently testing.

Verifying the circuits

The half and full adder truth-table tabs have a Verify all button that drives every input combination through the drawn circuit and ticks each row.

Developers can run DLS.selfTest() in the browser console: it applies test inputs to all five experiments and checks that every drawn wire and gate maps to a real netlist signal, shows the correct colour, and produces the arithmetically correct result. The logic engine also has a Node test-suite: node tests/logic.test.js.

Accessibility

All controls are keyboard reachable, input terminals in diagrams are focusable buttons, and the status line announces propagation changes.

Architecture

Connection with Intel 8086 Microprocessor

How the adders in these experiments relate to the arithmetic performed by the 8086 — and where the analogy stops.

Important clarification. These five experiments are simulations of digital arithmetic circuits. They are not an 8086 instruction-set emulator, and they do not reproduce the transistor-level or microarchitectural design of the 8086’s ALU. They model the textbook logic that any binary ALU must implement, so they explain what the 8086 computes for ADD, SUB, CMP, INC, DEC and NEG and how its flags are defined.

The role of the ALU

The 8086 is divided into a Bus Interface Unit (BIU), which fetches instructions and data, and an Execution Unit (EU), which decodes and executes them. The EU contains the Arithmetic Logic Unit: a 16-bit unit that performs addition, subtraction, increment/decrement, comparison and the logical operations (AND, OR, XOR, NOT) on 8-bit or 16-bit operands, and updates the FLAGS register.

How binary addition is performed

An instruction such as ADD AX, BX asks the ALU to add two 16-bit words. Logically this is exactly Experiment 3: bit i of the result is Aᵢ ⊕ Bᵢ ⊕ Cᵢ and the carry passes to bit i + 1. A plain 16-bit ripple chain would need ~33 gate delays, so real ALUs use faster carry techniques such as the look-ahead idea of Experiment 4. ADC (add with carry) feeds the previous CF into C0 — the Cin input of Experiments 2–4 — which is how multi-word numbers are added.

How subtraction uses two’s complement

SUB AX, BX computes AX − BX. Arithmetically this is AX + (~BX) + 1 — exactly Experiment 5 with M = 1: the B operand is inverted and the +1 enters as the carry-in. CMP performs the same subtraction but discards the result and keeps only the flags; NEG computes 0 − operand; SBB also subtracts the incoming borrow.

Carry and overflow flags

  • CF (carry) — unsigned view. After ADD it is the carry out of the most significant bit (Cₙ). After SUB/CMP the 8086 sets CF when a borrow occurred (unsigned destination < source) — the inverse of the adder’s carry-out in Experiment 5.
  • OF (overflow) — signed view. Set when the two’s-complement result is outside the representable range; equivalent to Cₙ ⊕ Cₙ₋₁ (the V output of Experiment 5).
  • ZF, SF, PF — result is zero; copy of the sign bit; even parity of the low byte.
  • AF (auxiliary) — carry or borrow between bit 3 and bit 4, used by DAA/DAS/AAA/AAS for BCD arithmetic.

About

About this simulator

Purpose

A browser-based laboratory for the arithmetic-circuit experiments of a digital electronics / microprocessors course. Students can operate each circuit, watch signals propagate, and connect what they see with truth tables, Boolean equations and the 8086’s arithmetic instructions.

How it works

  • Gate-level netlists. Every circuit is described as a list of gates (js/logic.js). The diagrams are drawn from the same signal names and coloured from the evaluated netlist, so nothing on screen is decorative.
  • Independent reference arithmetic (ripple, look-ahead, add/subtract, 8086 flags) is used for the explanations and cross-checked against the netlists by the test-suite.
  • No dependencies. Plain HTML, CSS, JavaScript and SVG. No backend, no build step, no external services — open index.html and it runs offline.

Limitations

  • Timing uses a unit-delay, structural (worst-case) model; real gates have different and data-dependent delays.
  • The look-ahead network is a single level with unlimited fan-in, as in textbook equations.
  • The 8086 section explains concepts and flag rules; it does not emulate instructions or the chip’s internal design.
